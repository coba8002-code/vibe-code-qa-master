# 0.9.0-rc2 자동 수정 및 실제 재검사

실행 검사 폴더를 런처에서 등록하고 웹 화면의 **AI 자동 수정 · 재검사**에서 시작합니다.
Codex CLI 로그인, Docker 엔진, `python:3.12-slim` 또는 `node:22-alpine` 로컬 이미지가 필요합니다.
Docker가 없는 PC에서는 정적 검수는 가능하지만 자동 수정은 실행 환경 오류로 안내합니다.

1. 원본에서 최대 100개 파일/512KB의 Python/Node 모듈을 별도 복사합니다.
2. 네트워크 없는 읽기 전용 Docker 마운트에서 기존 테스트를 실행합니다.
3. 실패하면 로그인된 Codex에 소스와 실패 결과를 보내 수정 JSON을 받습니다.
4. 기존 소스 파일만 변경합니다. 테스트/의존성 설정/새 파일 변경은 거부합니다.
5. 동일한 테스트를 재실행하고 정적 검사도 기록합니다. 최대 3회(화면 기본 2회) 반복합니다.
6. 결과와 합산 패치를 로컬에 보존합니다. 원본 수정, GitHub push 또는 배포는 하지 않습니다.

Codex는 읽기 전용 실행 모드로 사용하며 셸, 브라우저, 앱, 컴퓨터 조작, 훅, 다중 에이전트 도구를 비활성화합니다.
자동 수정 요청에는 별도 프로젝트 복사본의 소스가 포함됩니다. 인증 파일 이름 및 알려진 하드코딩 비밀값 패턴을 차단하지만,
모든 형태의 비밀값을 탐지하는 기능은 아니므로 전송 대상으로 지정하는 폴더에 비밀값을 보관하지 마세요.
AI 응답은 최대 180초이며 수정 결과는 테스트 통과 후에도 검토가 필요합니다.

검증 구분:
- Windows 단위/API 검사 및 실제 로컬 HTTP 성공/실패 부하 검사.
- 로그인된 Codex에서 실제 수정안 생성 확인(단순 덧셈 오류 샘플).
- Linux CI에서 해당 실제 수정안을 재생하여 Docker 기준 실패 → 수정 → 재검사 성공 확인.
- Linux CI에서 빈 테스트와 시간 초과 판정 검사.
- 2026-10-30 Windows 사용자 설치판에서 WSL 2.7.14 / Docker Desktop 4.97.0을 사용해 실제 Codex 호출과 Docker 재검사를 연속 실행했다. 샘플 테스트 2개 실패 → 수정 1회 → 같은 테스트 2개 통과를 확인하고 원본/테스트 파일 불변을 확인했다.
- 이는 임의의 대형 저장소나 모든 기능/E2E/보안 테스트 통과를 보증하지 않습니다.
- Claude 자동 실행, 패키지 설치, PR 생성 및 코드 서명은 포함하지 않습니다.

CI 재생 테스트는 실시간 AI 호출이 아니며 CI에 개인 자격 증명을 넣지 않습니다.
Docker가 없는 다른 PC에서는 환경 준비가 필요합니다. rc2는 일반 바탕화면 실행에서도 설치된 Codex와 Docker 경로를 찾고, 자동 갱신 중 펼쳐 둔 결과를 유지합니다.
앱 재시작 시 진행 중 작업은 중단 상태로 표시합니다.
